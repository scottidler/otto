# Otto's on-disk layout

Regenerated by running otto against a scratch `$OTTO_HOME` and `find`-ing the result (a producer/consumer pair, so both an `input.*` and an `output.*` file appear).

```
$OTTO_HOME/                             # default $HOME/.otto
  otto.db                               # SQLite metadata (see docs/architecture/sqlite-integration.md)
  .last_prune                           # marker file for the auto-prune-on-startup cooldown
  <project-name>-<hash>/                # e.g. proj-70af3bf4/; hash is 8 hex chars of the ottofile path
    .cache/                             # rendered scripts, flat, named by content hash - no per-task subdir
      <hash>.sh                         # e.g. 734d509e.sh
      <hash>.sh
    <timestamp>/                        # run directory, named by Unix start time; e.g. 1788438233
      run.yaml                          # serialized ExecutionContext: prog, cwd, user, timestamp, hash, ottofile, args
      tasks/
        <task-name>/
          script.sh -> ../../../.cache/<hash>.sh   # relative symlink to the cached script
          builtins.sh                   # otto's injected bash prologue (source_env, otto_serialize_output, ...)
          stdout.log
          stderr.log
          output.<task-name>.json       # this task's output, keyed by its own name
          output.<task-name>.env        # same output, bash-sourceable (jq-free consumers)
          input.<dep-name>.json         # present only if this task depends on <dep-name>; that dependency's output
          input.<dep-name>.env          # same input, bash-sourceable
    <timestamp>-<n>/                    # a second run starting in the same wall-clock second as another; n = 1, 2, ...
```

There is no `artifacts/` directory, no `env.yaml`, `metadata.yaml`, or `cmdline.yaml` — `run.yaml` is the only per-run metadata file, and it holds all of the fields above, not a copy of the ottofile. There is no top-level `.cache/` under `$OTTO_HOME`; the cache is per-project, inside `<project-name>-<hash>/`.

## Naming

- **Project directory**: `<name>-<hash>`, where `<name>` comes from the ottofile's parent directory (or the ottofile's own name) and `<hash>` is 8 hex characters of a hash of the canonical ottofile path. Two otto projects with the same directory name but different paths get different hashes and never collide.
- **Run directory**: the Unix timestamp (seconds) the run started, alone if it's the only run to start that second, or suffixed `-1`, `-2`, ... for every run after the first that starts in the same second. `otto History --json`'s `run_dir` field is this path, recorded once at run start rather than reconstructed later.
- **Cache file**: a hash of the *rendered* script content, flat inside `.cache/` (not `.cache/<task>/<hash>` — there is no per-task subdirectory, since the same rendered script can be shared by any task whose content happens to match).

## What a real run writes

```
$ find $OTTO_HOME/proj-70af3bf4
proj-70af3bf4/1788438265/run.yaml
proj-70af3bf4/1788438265/tasks/down/{builtins.sh,output.down.env,output.down.json,script.sh,stderr.log,stdout.log}
proj-70af3bf4/1788438265/tasks/up/{builtins.sh,input.down.env,input.down.json,script.sh,stderr.log,stdout.log}
proj-70af3bf4/.cache/{31f7fa16.sh,591648c6.sh}
```

(`up` depends on `down` in this example, hence `input.down.{json,env}` inside `up`'s task directory.)
